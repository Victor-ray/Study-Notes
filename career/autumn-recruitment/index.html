01先看节奏，再安排准备

2028 年毕业，倒着看这条时间线

下面是建议的准备节奏。点击阶段，看看当时最值得做什么；实习、准备和投递可以交叉进行。

把日期当提醒，不当统一开网日。2028 届秋招主要对应毕业前一年的招聘；具体毕业时间范围以企业公告为准。部分暑期实习项目会更早开放，不能等到 2027 年 3 月才开始关注。比如汇丰 2027 暑期项目已在 2026 年设置申请截止日；毕马威实习项目页则区分寒假、暑期和常规实习。上述案例仅说明节奏差异，不代表目前仍可投递。

02值得提前投入的一件事

暑期实习的重要性，在于它能连接秋招

对于方向未定的你，日常实习可以帮助探索；暑期实习则是毕业前一年值得重点关注的机会。两者可以衔接，不必只等暑假。

让简历有真实内容可讲

真实任务会带来业务背景、协作过程和问题处理经历。面试时，可以讲清自己做了什么、为什么这样做、如何确认效果。

要积累的不是一行公司名，而是一段能经得住追问的经历。

验证自己是否喜欢这个方向

岗位名字和每天做的事不一定相同。实习能帮助你判断工作内容、团队方式和能力要求，给后续选择提供依据。

比起“我好像喜欢产品”，更具体的是“我愿不愿意持续做需求分析和沟通”。

关注转正与后续招聘机会

部分实习项目设有留用或转正安排，也有项目以体验和短期工作为主。投递时就看清项目类型，提前询问考核方式。

“有转正机会”不等于一定留用；保留正常参加秋招的准备。

第一份实习，先看能接触到什么

是否能做具体任务？是否有人指导和反馈？结束后能否讲清一项自己的贡献？结合方向匹配、时间成本和实际工作内容选择，不只看岗位名称。

投之前，把这几件事问明白

最早到岗时间每周到岗天数最短实习时长工作地点与通勤具体工作内容是否设有转正

先协调课程、科研和导师安排，如实说明可投入的时间。尝试面试也应选择自己确实愿意了解、条件能够匹配的机会。

03提前整理，投递时少手忙脚乱

建一个「秋招申请材料」文件夹

证件照、成绩单、英语成绩和简历集中存放。文件命名清楚、版本可分辨，需要时就能直接找到。

海投太多时：允许“只记重点”

重点公司尽量完整记录；普通海投先利用平台里的投递记录，不要求自己事后逐条补账。等有回复、进入笔面试，再把这家公司补进飞书表。

有了笔面试：把日期和下一步记牢

收到通知就更新公司、岗位、时间与轮次；重要安排另加日历提醒。每次面试后贴上复盘链接，再写一句“下次前要补什么”。

这张表是帮你防漏事，不是统计工作量。先保证“哪些机会正在推进、下一步什么时候做”清楚，其他字段按需增加。复制的表头可粘贴到普通表格；使用多维表格时，也可以按这些名称建字段。

04把分散的信息，汇到一张投递表里

机会在哪里找？这些渠道搭配着用

官网用于确认和申请；平台、公众号、文档和 AI 用来拓宽线索。发现岗位后，记下原始入口、招聘对象和截止时间。

8 个渠道 · 先发现，再核对
官

企业招聘官网

确认岗位职责、毕业时间范围、投递入口和批次。优先收藏目标企业的招聘页，直接查看原始公告。

入口示例：小米招聘适合：确认信息、正式申请

学校就业网 / 宣讲会

查看校内招聘、宣讲和双选会。了解企业面向本校开放的岗位，也可关注学院和就业中心的通知。

适合：校内机会、线下交流
聊

BOSS 直聘 / 牛客

BOSS 用于搜索岗位、与招聘方沟通；牛客可结合职位信息和面经了解要求。核对日常实习与校招的区别。

打开牛客适合：找实习、交流与面经
纸

小纸团求职

通过校招看板、微信小程序等入口发现招聘信息。用来补充企业清单，再核对岗位原始公告。

查看产品官网适合：聚合信息、补充线索
微

招聘公众号

关注目标企业的官方招聘号与学校就业号，跟踪开放、宣讲和截止提醒；汇总号的信息回到原公告核对。

适合：订阅动态、补充提醒

小红书里的汇总文档

搜索实习或校招信息表，留意面向届别、行业和最近更新时间。将相关岗位加入自己的投递表，避免重复收藏。

适合：扩展公司名单、找经验

让能联网的 AI 按毕业年份、城市和方向查找岗位，提供原始公告及核对日期。没有来源的结论先作为线索。

适合：跨渠道查找、整理线索
O

来个 Offer

也可以纳入日常关注的渠道。此名称存在相近产品，具体使用哪一个入口，后续结合分享者常用的链接补充。

具体入口：后续补充

给 AI 一个能核验的任务，而不只问“有什么岗位”

“我是预计 2028 年毕业的硕士生，方向暂未确定，请按岗位类别寻找实习机会。列出招聘对象、城市、到岗要求、截止日期、官方原始链接和核对日期；无法确认的明确标注，不要把历史岗位当成当前开放。”

找到一条机会后，至少记下：公司 / 岗位 / 城市 / 招聘对象 / 原始链接 / 截止日 / 进度 / 下一步。官网未写截止日时，记录“未注明”，不要自己猜。

05方向未定，先建立准备方法

八股要准备，也要准备好“我做过什么”

开发岗的“八股”通常指常见基础知识问答。不同岗位考察不同，不用先背一整套技术题，再决定自己投什么。

先缩小范围，再集中补短板

可以先选 2—3 个有兴趣的岗位类别，各看几份职位描述（JD），比较具体工作与能力要求。

  1. 找出反复出现的基础能力
  2. 对照已有的项目与经历
  3. 用尝试面试发现真正的缺口
  4. 形成一份下周能执行的补齐计划

不管投什么，都先准备这三件事

  • 自我介绍能在约 1 分钟内说明背景、相关经历、想了解的岗位，以及可实习的时间。
  • 经历表达选一段项目、科研或活动经历，讲清背景、个人任务、具体行动、结果与不足。
  • 岗位理解了解这个岗位每天做什么，为什么感兴趣，自己的哪些经历可以迁移过去。

根据具体技术方向选题，不要求全部掌握

  • 技术基础围绕 JD 补编程语言、数据结构、数据库、网络等；AI 应用岗再按需了解模型调用、检索和评估。
  • 项目追问讲清输入、处理过程、输出、个人负责的模块，以及真实遇到的问题和验证方式。
  • 实践与表达能按要求完成代码题或实践任务；基础问题练到能解释机制、举例并说清边界。

产品和运营不是同一种岗位，按具体职责准备

  • 问题分析产品侧练习用户、场景、需求与取舍；运营侧结合内容、用户、活动或增长的具体职责。
  • 经历证据用已有调研、项目、活动或内容实践说明行动依据、个人贡献、反馈和可核对的结果。
  • 案例表达选熟悉的产品或业务做一次分析，说明判断依据、衡量指标以及如何验证自己的假设。

把工具能力放在业务问题中解释

  • 基础工具按 JD 练习 SQL、表格与所需编程工具，理解基本统计概念和数据质量检查。
  • 业务分析把问题拆成指标、口径和分析路径，解释为什么这样比较，以及数据能支持什么结论。
  • 项目表达准备一个完整分析案例：问题、数据、方法、发现、建议与局限，不只展示图表。

以上是准备维度示例，具体面试内容以目标岗位为准。没有经历的部分，如实说出自己的学习与实践进度。

看 JD，选方向→补基础，讲经历→投递与面试→复盘后再调整

06每次面试，都留下下一次能用的东西

面试结束后，把“不会”变成具体动作

结果可能需要等待，但复盘可以马上开始。当天结合笔记或录音整理问题，再和 AI 探讨没答好的地方，把下一次怎么改写清楚。

  1. 01

    先还原，不只记一道题

    记录问题原意、追问链和自己当时怎么答。区分“没学过”“理解不深”“项目讲不清”和“表达没组织好”。

  2. 02

    找原因，不把猜测当结论

    有反馈就记录原话；没有反馈，不凭一次结果断定失败原因。先修正自己能确认的问题，再观察后续面试。

  3. 03

    补一项，练一次，再验证

    给短板写出一个具体任务和完成时间。整理答案后再口述一次，下一场留意类似问题能否讲清楚。

例如（方法示例）：“项目追问没答好” → 画清流程、补上自己负责的部分，再用 3 分钟讲一遍。没有测过的效果不写成成果。

可以直接复用的复盘模板

公司 / 岗位 / 日期 / 面试轮次 面试时长、岗位链接、使用的简历版本： 录音 / 转写稿位置（如有）： 这次问了什么？ 问题与追问： 我的实际回答 / 卡住的位置： 讨论后补齐的思路 / 仍待核实的内容： 问题出在哪里？ 知识缺口 / 经历证据 / 表达组织 / 岗位理解： 面试官明确反馈（如有）： 下一步怎么补？ 一个具体改进任务 + 完成时间： 下次如何验证： 流程状态 / 下一次跟进日期：

推荐：千问录音摘要，辅助面试复盘

把录音留下来，把没有答好的问题继续聊透。
打开千问

面试时容易漏记追问，也不一定记得自己具体怎么答。可以借助千问的录音摘要 / 转写功能，把面试过程整理成文字，再围绕没回答上来、答得不完整的问题继续追问和讨论。

  1. 01录下来，转成文字

    在对方同意、面试规则允许时录音。通过可用的录音转写入口整理文字稿，先核对专业词、说话人和关键句。

  2. 02找出没答好的问题

    让千问梳理“面试官的问题 → 我的实际回答 → 后续追问”，再由自己确认哪些地方没答上、答偏了或缺少依据。

  3. 03围绕卡点逐题讨论

    一次选一道题：考察什么？我缺了哪个知识点或经历细节？请它先提问引导，再用例子解释，补齐完整回答。

  4. 04自己重答，写回复盘

    脱离 AI 答案重新口述一遍，把补齐的思路、待核实内容与下次行动写进模板，检查自己是否真的能讲清。

不要只说“总结一下”，可以这样发给千问

“请先依据转写稿整理问题、我的原回答和追问。围绕我标记的没答好问题，一次讨论一道：先分析考察点，再通过提问和例子帮助我补齐，最后让我重新回答。请区分原话、你的分析和补充知识，不要替我编造经历。”

用的时候留意：功能名称、入口与可用范围以当前客户端为准；若没有直接转写入口，也可先把录音转成文字，再交给千问讨论。录音和上传前征得相关人员同意，去除个人及企业敏感信息。摘要回看原文核对，知识点再查可靠资料；AI 的分析不等于面试官的真实评价。

不用一次做完所有准备

这周，先做四件小事。

先完成一个能运转的起点，
后面再根据机会和反馈调整。

1
整理材料与一版简历先做到可投递，后续再按岗位修改。
2
看几份不同方向的 JD记下工作内容、能力要求和自己的疑问。
3
选几份合适的实习尝试申请先核对招聘对象、到岗时间与地点。
4
建投递表，约定复盘时间不只收藏机会，让每次尝试都有下一步。
